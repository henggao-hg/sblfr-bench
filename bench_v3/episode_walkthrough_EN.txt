------------------------------------------------------------------------------
0. Three actors
------------------------------------------------------------------------------

  [Agent]      = a large language model (here, Qwen3.7-Max).
               The only "thinking" component. Each turn it sees one "visible
               observation", reasons in natural language, and emits exactly ONE
               JSON action. It never sees any true underlying value of the lab,
               and it is never told whether a fault exists or which fault it is.

  [Verifier]   = a plain program (NOT an AI). The legality gate.
               Every proposed action passes through it first: schema valid?
               resources sufficient (non-negative volume & moles, vessel
               capacity, available stock, not quarantined)? invariants intact?
               Illegal -> rejected; legal -> passed through. It judges only
               "is this allowed", never "is this wise".

  [Simulator]  = another plain program (NOT an AI). The real world + ground-truth
               ledger. It holds all hidden truths (true concentrations, true
               volumes) and the one injected fault (here: the assay instrument
               reads systematically low). A passed action is executed here; it
               advances the true state and returns ONE thing to the Agent --
               an instrument reading or a receipt -- and that reading has already
               been corrupted by the fault.

------------------------------------------------------------------------------
1. The per-turn loop (repeated every step)
------------------------------------------------------------------------------

   Simulator emits the "visible observation" (JSON)
        |
        v
   [Agent] reads obs -> reasons in NL -> proposes 1 JSON action
        |               (may include a rationale field)
        v
   [Verifier] checks schema / resources / invariants
        |                       \-- illegal --> reject, ask to retry
        | legal
        v
   [Simulator] executes, updates hidden truth, returns one result (reading/receipt)
        |
        v
   the action (redacted) is appended to action_log -> next observation -> next turn

   Budget = 8 actions. If they run out with no closing action
   (no accept_batch / no abort_and_handoff) the episode counts as "unmanaged".

------------------------------------------------------------------------------
2. What the Agent CAN and CANNOT see each turn
------------------------------------------------------------------------------

  Visible (the observation JSON fields):
    - goal           target: bring X in vessel_1 to 0.4 M, tolerance +/- 0.02 M
    - vessels        each vessel's liquid VOLUME and CAPACITY
                     (NOT the true concentration inside)
    - stocks         each stock's LABEL concentration + ledger volume remaining
                     (the label is a claim, not the truth)
    - standards      reference standards' CERTIFIED concentration (trusted anchor)
    - instruments    an instrument exposes ONLY {what it measures, which species}
    - initial_protocol_record   what the nominal protocol did
    - action_log     every action so far + its returned result
                     (eval-only fields such as the rationale are stripped out)
    - action_budget  steps used / steps remaining

  Hidden (lives only inside the Simulator and the eval transcript):
    - any true concentration / true volume
    - whether a fault exists, and which class of fault
    - the instrument's real distortion (gain, bias)
    * KEY DESIGN (Amendment G): the instrument does NOT tell the Agent whether it
      is healthy. To learn if it is trustworthy, the Agent must measure a standard
      whose answer is already known and infer the error from the discrepancy.

4. MY commentary (this section is my interpretation, not the transcript)
------------------------------------------------------------------------------

  - The interaction is a closed loop: observation -> reasoning -> action ->
    legality gate -> execution -> new observation. The Agent decides under
    partial information; the truth is held by the Simulator and leaks out only
    through (corrupted) readings.

  - Neither the Verifier nor the Simulator is an AI; both are deterministic
    programs, so the right/wrong judgment is objective and the Agent cannot see
    the answer key.

  - The injected fault here is "instrument reads low". A naive agent would believe
    the 0.33361 reading and top up the batch -- pushing an already on-target batch
    out of spec (our scoring calls that e_broke_good, the most severe failure).
    In this transcript Qwen3.7-Max instead measured the batch, cross-checked
    against the stock, diagnosed the instrument with two certified standards,
    recalibrated, re-measured, and accepted -- never altering the batch itself.

  - This is exactly the Amendment G design: the instrument will not report its own
    health, so diagnosis requires measuring known standards. It separates models
    that can do this from models that cannot.
